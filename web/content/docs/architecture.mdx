## How a document is processed

<ol className="ob-flow">
  <li><strong>Detect layout</strong><span>Match the extension, signatures and layout headers.</span></li>
  <li><strong>Read source</strong><span>Extract fields, grid positions and raw text from the appropriate provider.</span></li>
  <li><strong>Normalise</strong><span>Build records with exact decimals, dates, currencies and links.</span></li>
  <li><strong>Prove</strong><span>Run arithmetic and independent evidence checks, then validate the schema.</span></li>
</ol>

Statement batches check opening balance plus signed movements against closing, as well as running balances and continuity where applicable. Settlements check row and total arithmetic. Tax providers add their own gates. A mismatch or missing independent check ends with a typed refusal.

## Runtime paths

~~~text
Python application  ── process() ─────────────────→ Python engine
Node.js application ── typed wrapper ── subprocess → Python engine
Browser workspace   ── Next.js ── private HTTP ────→ FastAPI → Python engine
~~~

The Python engine owns the parsing contract. The Node.js wrappers validate the documents they receive and optionally restrict accepted layouts. The Next.js web tier proxies uploads and streams decisions from FastAPI. Files are staged in a per-run temporary directory and cleaned up after processing. Workspace history and released outputs are kept in the user's browser. A deployment can enable Q&A for released documents, with deterministic calculations made by application code.

## Provider boundaries

`openbooks.core` owns format detection, normalisation, validation and the provider registry. `openbooks.statements` handles bank files and the PDF/OCR front end. `openbooks.gateways` handles payment exports, `openbooks.tax` supplies tax and workpaper parsers, and `openbooks.doctor` reports install health.

Providers are registered using Python distribution entry points such as `openbooks.layouts`, `openbooks.sniffers`, `openbooks.frontends` and `openbooks.gates`. Install editable packages with pip when developing so their entry points are available. Layout recognition and provider registration are separate: registering a parser does not by itself teach the detector a new header or signature.

See the [engine HTTP API](/docs/engine-api), [model guide](/docs/model), and [MCP integration](/docs/mcp) for the other runtime paths.
