Open Books reads bank statements, payment settlements, tax documents, and Excel workpapers. For each file, it returns a complete `openbooks.v1` document with verification checks and source evidence, or a typed refusal that explains why the file could not be released.

## Build and test an integration

Once you've run the sample, [build a bank statement importer](/docs/build-an-importer) that saves each decision and computes exact debit and credit totals. Then [test your integration](/docs/test-an-integration) with bundled bank, PDF, settlement, and tax fixtures. The test guide covers invalid inputs, interrupted runs, retries, and what a reviewer should be able to trace.

## How a file becomes verified JSON

1. **Detect the layout.** Open Books identifies a table or file structure it knows how to read. Two CSV files can have different layouts even when they use the same extension.
2. **Extract and normalize records.** The engine reads values such as dates, debits, credits, and balances into a consistent schema. It records the source text and its location when available.
3. **Verify against the source.** For a bank statement, the engine can check that opening balance plus credits minus debits equals the closing balance. At least one check must use independent evidence from the document, such as a printed closing balance.
4. **Return a decision.** A release has `status: "ok"` and includes records, assertions, and evidence. A refusal has `status: "refused"`, `data: null`, and a code you can act on. Read the status before importing records.

## Choose an integration

| Where you work | Start here | Use it for |
| --- | --- | --- |
| Browser | [Workspace](/docs/workspace) | Explore synthetic samples and review a batch by hand. |
| Terminal | [CLI reference](/docs/cli) | Run local files, save JSON, and script jobs with exit codes. |
| Python 3.11+ | [Python API](/docs/python) | Call the engine inside a Python process and pass context per file. |
| Node.js 20+ | [Node.js and TypeScript](/docs/node) | Invoke the local Python engine and handle typed results. |
| Application server | [Self-hosted HTTP API](/docs/engine-api) | Send uploads to a private engine and track per-file decisions in a stream. |
| AI agent | [Model Context Protocol](/docs/mcp) | Run supported operations from an MCP client and retrieve parts of the proof. |
