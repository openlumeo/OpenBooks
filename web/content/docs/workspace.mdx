[Open the workspace](/app) to process and review files in your browser. A batch groups files into one run. Each file still gets its own decision, so a refusal in one statement can appear alongside a release for another.

## When to use this

Use the workspace to check a few files by hand, review their checks and evidence, and download the decision. For batch imports from your own code, use [Python](/docs/python) or [Node.js](/docs/node).

## 1. Run two sample statements

1. Open the sample picker and add **Bank statement CSV** and **Bank CSV without an opening balance**. The picker supplies the parameters configured for each fixture.
2. Run the batch. The first statement releases. The second refuses because it needs an opening balance.
3. Open the refused card. Enter `1000.00` in **Opening balance** and rerun that file. Use this amount for the sample. For real files, verify the opening balance against an authoritative source.

## 2. Inspect and export a release

1. On a released card, open **Data** to inspect the parsed records.
2. Open **Checks** and read the expected and computed amounts. An independent check uses a value from the input, such as a printed balance.
3. Open **Evidence** to locate the relevant source text, row, or page. For PDFs and images, the evidence can include a bounding box around the text.
4. Choose **Download JSON** to save the complete decision, including the records, checks, and evidence. See [the output contract](/docs/output-contract) for field definitions.

## 3. Run your own files

Check the [format matrix](/docs/formats), then attach the original exports. Open **Params** to supply verified currency, date order, or opening balance where required. Review each file's outcome:

| Outcome | What to do |
| --- | --- |
| Released | Inspect the records, checks, and evidence before exporting. |
| Refused | Read the code and message. If the card asks for a field, supply its verified value and rerun. You can also download the refusal for review. |
| Interrupted | Use **Retry file** when the original is still available. If prompted, choose **Attach original file** and select the same export again. |

## History and questions

The hosted workspace processes uploads on the server and stores thread history in this browser. After a reload, you can review saved results, and a retry may ask for the original file again. Use [local Python](/docs/python) or [local MCP](/docs/mcp) if you need the extraction to run on your own machine.

When Q&A is enabled, you can ask about released files in the current thread. Try asking which transactions contributed to a total and request the source records. Application code computes totals and counts. Answers can cite files or record IDs. Deployments with the optional linker can also report [payout matches](/docs/payment-settlements).

## Common refusals and what they mean

The refused card shows the code and message from the engine.

- `PARSE_ERROR`: a required value, such as the opening balance, is missing or unreadable. Supply the verified value in **Params** and rerun.
- `BALANCE_MISMATCH`: a check failed or no independent balance was found. Compare the file with the original export before retrying.
- `UNKNOWN_LAYOUT`: no supported layout matched the file. Compare it with the [format matrix](/docs/formats).
- `UNSUPPORTED_INPUT`: the file type, size or structure is not supported. Check whether a PDF is locked.
- `LOW_CONFIDENCE`: the OCR or model reading was not confident enough. Review the scan quality and orientation.
- `OUTPUT_INVALID`: the result failed contract validation. Keep the download for review.

See the [refusals page](/docs/refusals) for the full list and retry guidance.
